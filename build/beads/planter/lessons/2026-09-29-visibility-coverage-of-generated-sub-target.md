# Visibility coverage of generated sub-target callers (fidl library <name> rust/ cpp bindings) and callers outside the local product graph after bazel2gn visibility conversion

- **Learned from:** cq failure on [CL 1850715](https://fuchsia-review.googlesource.com/c/fuchsia/+/1850715), patchset 1 (task `pkg-update-fidl`)
- **Date:** 2026-09-29
- **Changed:** `checks/manifest.json`, `checks/visibility_audit.sh`, `tools/find_rdeps.sh`, `tools/manifest.json`

## Root cause

visibility_audit and find_rdeps counted a caller toward a Bazel target only when
the label named that exact target, so references to GN sub-targets generated by
fidl_library (e.g. :<fidl>_rust) were dropped from the per-target caller sets.
find_rdeps therefore recommended a one-entry list, and visibility_audit flagged
the correct entries, including the internal-tree rollup, as false positives. No
check confirmed that every real caller is covered, and the local fx build does
not load callers in other products or the internal tree, so only CQ caught the
GN 'Dependency not allowed' error.

## Why not a one-off fix

Adding the missing entry to one BUILD.bazel fixes only this library. Every
future fidl_library, or any rule that emits <name>_<suffix> sub-targets, would
get the same wrong per-target recommendation and the same false-positive
pressure to drop needed entries, and would again fail only in CQ. The caller
attribution in the shared tool and check has to be fixed, plus a deterministic
coverage check for all migrations.
