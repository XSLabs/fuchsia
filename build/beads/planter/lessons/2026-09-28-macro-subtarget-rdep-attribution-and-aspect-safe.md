# Macro subtarget rdep attribution and aspect safe wildcard builds

- **Learned from:** inner loop friction on a local task (task `pkg-update-fidl`)
- **Date:** 2026-09-28
- **Changed:** `checks/build_verification.sh`, `checks/visibility_audit.sh`, `prompts/coder.md`, `tools/find_rdeps.sh`

## Root cause

First, find_rdeps.sh and visibility_audit.sh only attributed a reverse
dependency to per_target_rdeps[t] when the label subtarget matched t exactly (or
default_target in a single-target package), ignoring macro-generated binding
subtargets with '<t>_' or '<t>.' prefixes (such as '<t>_rust', '<t>_cpp',
'<t>_hlcpp', and '<t>_zither' generated by fidl_library); this left
per_target_rdeps empty and caused visibility_audit.sh to flag every valid caller
in visibility as a false_positive_rdep_visibility error. Second,
build_verification.sh invoked 'fx bazel build --config=fuchsia_platform
//<dir>:all', which expanded internal '_validate_json_action' targets
('<name>_validate_ir_json' from fidl_library) as top-level targets where the
globally enabled assert_no_deps_aspect crashed iterating over the single-Target
'data' attribute.

## Why not a one-off fix

Every FIDL library and multi-binding macro across the Fuchsia tree generates
language-specific subtargets ('_rust', '_cpp', '_hlcpp', '_zither') and internal
'_validate_ir_json' ('_validate_json_action') rules. Fixing only a single
package directory would leave visibility_audit.sh rejecting valid callers and
build_verification.sh crashing in assert_no_deps_aspect on every future FIDL or
JSON-validated package migration.
