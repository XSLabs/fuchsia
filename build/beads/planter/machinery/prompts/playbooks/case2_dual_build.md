# Playbook: Case 2 Dual-Build (bazel2gn)

- Maintain BUILD.bazel as the source of truth and keep BUILD.gn synchronized via `fx bazel2gn -d <target_dir>`.
- Verify that `## BAZEL2GN SENTINEL - DO NOT EDIT BELOW THIS LINE ##` is present in BUILD.gn and that `//<target_dir>:verify_bazel2gn` is added to `bazel2gn_verification_targets` in `//build/bazel2gn_verification_targets.gni` (or `//sdk/fidl/bazel2gn_verification_targets.gni`).
- **Complete Target Migration & Ban on Target-Level `# @bazel2gn:skip` for Convertible Libraries**:
  - NEVER put `# @bazel2gn:skip` above a convertible library, binary, or code target in `BUILD.bazel` (`fx_cc_library`, `cc_library`, `fx_cc_library_headers`, `cc_binary`, `fx_cc_binary`, `rustc_library`, `rustc_binary`, `rustc_proc_macro`, `rustc_test`, `go_library`, `go_binary`, `go_test`, `py_library`, `py_binary`, `fidl_library`, `zither_fidl_library`, `idk_cc_*`) while leaving a manual GN target (`static_library`, `source_set`, `executable`, `rustc_library`, etc.) above the `BAZEL2GN SENTINEL` in `BUILD.gn`.
  - **Reference & Bitrot-Prevention Targets Must Be Synced via `bazel2gn`**: Targets in `BUILD.gn` that exist to compile reference C/C++ implementations of assembly routines or prevent bitrot (and are depended upon by `group("tests")` in `BUILD.gn`) MUST be migrated to `fx_cc_library` / `cc_library` in `BUILD.bazel` WITHOUT `# @bazel2gn:skip`, and their manual `static_library` / `source_set` above the sentinel in `BUILD.gn` MUST be removed so `fx bazel2gn` generates the target below the sentinel.
  - **Translating C/C++ `copts` to GN `configs` (`# @bazel2gn:raw_overwrite`)**: When a C/C++ target in `BUILD.bazel` needs compiler flags in `copts = [...]` (e.g., `["-O3", "-fno-omit-frame-pointer", "-mno-omit-leaf-frame-pointer"]`) that are not in `bazel2gn`'s built-in `coptToConfig` table and instead correspond to GN `configs` (`//build/config:optimize_speed`, `//build/config:frame_pointers`, or a local `:leaf-frame-pointer` `config(...)` kept above the sentinel in `BUILD.gn`), place `# @bazel2gn:raw_overwrite:[ "//build/config:optimize_speed", "//build/config:frame_pointers", ":leaf-frame-pointer" ]` on the closing `],` of `copts = [...]` in `BUILD.bazel`. `bazel2gn` converts `copts` to `configs += [...]` using the `raw_overwrite` list so the entire `fx_cc_library` syncs cleanly to `static_library(...)` in `BUILD.gn`.
  - Above the `BAZEL2GN SENTINEL` in `BUILD.gn`, only keep GN-only constructs that have no `bazel2gn` equivalent (`import(...)`, `config(...)`, `group("tests")`, `fuchsia_test_component`, `fuchsia_test_package`, `fuchsia_unittest_package`, `fuchsia_component`, `fuchsia_package`, `resource`, `host_test_data`, `license`, `fuchsia_fuzzer_*`).
- **Visibility & bazel2gn Parity**:
  - Aim for Bazel-correctness over GN-workarounds in `BUILD.bazel`: never add `":__pkg__"` to a `visibility = [...]` list in `BUILD.bazel`. Same-package visibility is implicit in Bazel and `fx bazel2gn` automatically appends `":*"` in `BUILD.gn`. Do NOT inspect or modify `//build/tools/bazel2gn/**` or `//build/**/*.gni` during package migrations.
  - Scope `visibility` per-target strictly to true reverse dependencies (`deps`, `public_deps`, `test_deps`, `proc_macro_deps`, `actual`) using `per_target_recommended_visibility` from `find_rdeps`. Exclude any package that merely mentions the target inside its own `visibility` allowlist (`visibility.gni`) or only depends on GN-only targets above the sentinel (`:tests`, `:benchmarks`, `:verify_bazel2gn`).
  - **Globally-Used Platform Libraries & Test Utilities (`per_target_is_globally_used = true`)**: When a shared library or test utility is used across `>= 6` distinct top-level areas and would require `> 15` narrow visibility entries (`>= 20` rdep packages), do NOT replace `default_visibility = ["//visibility:public"]` with a sprawling 20–50+ line allowlist of leaf `:__pkg__` entries ("too narrow"). Instead, set target-level `visibility = ["//visibility:public"]` (or a concise `<= 15`-entry 2–3 level area rollup) as returned by `per_target_recommended_visibility`, and re-run `fx bazel2gn` so `BUILD.gn` gets `visibility = [ "*" ]`.
  - Never use `"//:__subpackages__"`, top-level `"//src:__subpackages__"` / `"//sdk:__subpackages__"`, or multi-domain umbrella wildcards (`"//src/lib:__subpackages__"`, `"//sdk/lib:__subpackages__"`).
  - For non-global targets (`<= 15` narrow entries), never collapse external callers into a cross-area depth-2 `"//src/<area>:__subpackages__"` wildcard (such as `"//src/storage:__subpackages__"`, `"//src/connectivity:__subpackages__"`, or `"//src/starnix:__subpackages__"` on a target defined outside `//src/<area>`). Instead, grant visibility to the specific `:__pkg__` packages or depth >= 3 component subtrees (`//src/<area>/<subcomponent>:__subpackages__`) that actually depend on the target, and re-run `fx bazel2gn` to sync `BUILD.gn`.
- **Build-Only Scope**:
  - The dual-build change must only touch `BUILD.bazel`, the regenerated `BUILD.gn`, and build registration lists (e.g., `//build/bazel2gn_verification_targets.gni`). Never edit source files (`.rs`, `.cc`, `.h`, `.py`, `.fidl`, `.cml`, etc.).
  - When converting GN `configs += [ "<lint config>" ]` to Bazel `lint_config = "<label>"`, verify the resulting lint set matches GN. New clippy/compiler errors mean attribute drift: fix the Bazel attributes, never the Rust/C++ code. If parity is impossible, stop and report.
  - Remember: GN appends `lint_config` / `configs` on top of the default lint configs, Bazel `lint_config` replaces the macro default. Test crates generated by `with_unit_tests = True` are compiled with the same `lint_config`, so lints in `#[cfg(test)]` code may newly surface. Leave test code untouched as well.
  - If (and only if) Bazel clippy then fails on test code, follow coder rule 6: explicit `rustc_test` named `<crate>_lib_test` whose `lint_config` is the label of the area's test-flavored `rust_lint_config` itself (add it next to the production config if missing). No source edits, no `raw_overwrite` on `lint_config`, no `clippy_warn_default` substitution, no new `alias()`.
  - Before finishing, confirm `git status --porcelain` / `git diff --name-only $PLANTER_CHANGE_BASE` list only build-definition files.
- **Shared Lint Configs (coder "Shared Lint Config Reuse")**:
  - Point `lint_config` at the `rust_lint_config` that defines the lints, or at a wrapper label that already existed before the change. Never add a Bazel `alias()`/wrapper or a GN forwarding `config()` that only renames or relocates a lint config.
  - bazel2gn copies `lint_config` verbatim into BUILD.gn: the label's package must have a same-named GN `config()` next to the Bazel `rust_lint_config`, holding only the area-specific rustflags.
  - Area `rust_lint_config`s load the default clippy/rustc dicts from the `.bzl` in `//build/config/rust/lints` and spell out only their own entries. If the defaults are still private dicts in that BUILD.bazel, export them to a `.bzl` in the same change (dicts moved verbatim with their `LINT.IfChange`/`LINT.ThenChange` markers, existing `rust_lint_config` targets kept with the same names and contents and loading them, BUILD.gn `LINT.ThenChange` paths updated). This is allowed despite the `//build` restrictions above.
  - Replace copies of the defaults in any file you edit, even if they predate the change; the `shared_config_reuse` check fails the change otherwise.
